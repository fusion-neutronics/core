# API reference

The reference below is generated by mkdocstrings from the type stubs shipped
inside the installed `yani` wheel. Classes appear under their public names
(`yani.Material`, `yani.PulseSchedule`, ...) rather than the private `yani._core`
extension module they live in.

The members are grouped by what they are for. The `get_*`/`set_*` accessors
behind nuclear-data settings are documented as the settings themselves under
[Nuclear data settings](usage.md#nuclear-data-settings). Public submodules are
listed below under the names used in examples, such as
`yani.sources.Histogram` and `yani.shapes.FoilLump`.

## Nuclear-data uncertainty

`DataUncertainty` is passed to `Material.transmute()`, not read from it; the
sigmas and the coverage report it produces come back on `TransmutationResults`
above. `Estimate` and `LineEstimate` are what the derived quantities come back
as, a nominal value with the ensemble's spread beside it, from
`get_activity_uncertainty` and the three getters like it. What the uncertainty
covers, and what a sigma of zero does and does not mean, is in
[Nuclear-data uncertainty](usage.md#nuclear-data-uncertainty).

## Making data

The two below write sections only transport reads, so nothing here consumes
their output. They are on this wheel so that a data-generation script works
against either wheel, which the bindings repository pins with a parity test.
`convert_photon` carries its auxiliary tabulations, the same ones yamc's does.

::: yani.convert_neutron_transport
::: yani.convert_photon

The photonuclear converter preserves evaluated MF=3 cross sections and the
original ENDF sections. It does not enable photon-induced transmutation or
photon transport; see [TENDL photonuclear data](libraries.md#photonuclear-data-in-the-next-tendl-release).

::: yani.convert_photonuclear

## Reading data back

Both of these read a converted Arrow directory through the same loader transport
uses and return a description of what is in it, which is how a conversion is
checked without standing up a transport run. Neither goes through the
process-wide stores, and the photon one publishes none of the process-wide
photon grids, so inspecting two builds of the same nuclide or element in one
interpreter reports on each of them rather than handing back the first.

::: yani.read_nuclide_from_arrow
::: yani.read_element_from_arrow

The photonuclear readback validates its cross-section tables against the
preserved MF=3 source rather than invoking either transport loader.

::: yani.read_photonuclear_from_arrow

## Source distributions

The energy distributions used by irradiation spectra live in `yani.sources`.

::: yani.sources

## Self-shielding shapes

The lump shapes passed to `Material.transmute()` control its resonance
self-shielding correction; see [Self-shielding](usage.md#self-shielding).
